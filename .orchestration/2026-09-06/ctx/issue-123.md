# _agent-guidance#123 — InstructionsLoaded hook: a load-time receipt for the fleet guidance (verdict at load, AGENTS.md drift, instruction-bytes telemetry)

**Model:** Claude Opus 5 (`claude-opus-5`), effort `high`. Parent: #118. Depends on nothing open (gates lane; can start now). Opened by the orchestrator on Adam's request of 2026-09-05 ("identify any ways InstructionsLoaded hooks would help, then implement via agents"). A sibling issue in skills-evals uses the same event for per-arm delivery receipts in the eval harness; keep the receipt line format compatible (one JSON object per line: `file_path`, `memory_type`, `load_reason`, `bytes`, `sha256`, `ts`).

## Problem

The session-start verdict (`fleet-guidance: installed / current / DEGRADED`) reports what `fleet-memory.sh` did to the file, not what the session loaded. Between the hook and the model sit things the verdict cannot see: a `CLAUDE_CONFIG_DIR` the CLI does not read memory from; a block that was current at start and truncated later (on 2026-09-05 a test mutation in a review container cut `/root/.claude/CLAUDE.md` from 56,099 bytes to 154 while the session ran, and nothing said so until the next SessionStart); a repo `AGENTS.md` whose managed header is behind the installed guidance version, or edited above the `## Repo-specific additions` marker, which the per-session guidance has no way to notice; and the cost the header quotes by hand (19 copies = 332.3k tokens, measured 2026-08-29) with nothing measuring it per session. The CLI now emits an `InstructionsLoaded` event for every `CLAUDE.md` and `.claude/rules/*.md` load — `file_path`, `memory_type` (`User` / `Project` / `Local` / `Managed`), `load_reason` (`session_start` / `nested_traversal` / `path_glob_match` / `include` / `compact`), `trigger_file_path`, `parent_file_path` — observe-only, no decision control, its JSON output discarded. It is the load-time receipt the verdict lacks.

## Do

1. **`.claude/hooks/instructions-loaded.sh`** (bash, `set -euo pipefail`, no network; honours `FLEET_GUIDANCE_SKIP` by doing nothing). On each event: (a) `memory_type: User` and the file carries the fleet block: compare the block's `fleet-guidance-version:` line and byte length against the state `fleet-memory.sh` recorded at install (add a small state file under `$CLAUDE_CONFIG_DIR`, e.g. `fleet-guidance.state` with version and bytes, written by the SessionStart hook — the only change to that hook; its existing tests stay unchanged and are extended); emit `fleet-guidance: loaded (v<id>, <n> bytes)` or `fleet-guidance: LOAD MISMATCH — <reason>` (truncated / stale version / block absent). (b) `memory_type: Project` and the file carries the managed header: compare the header's version to the installed guidance version and hash the managed region (above the marker) against the synced template recorded in the state file; emit `agents-md: current`, `agents-md: BEHIND (v<x> < v<y>)` or `agents-md: EDITED ABOVE THE MARKER`. (c) Every event: append `{ts, load_reason, memory_type, path (relative to `$HOME` or the cwd, never absolute), bytes, sha256}` to `$CLAUDE_CONFIG_DIR/instructions-log.jsonl`, rotated at 1 MB. Measure first where this hook's stdout lands on the current CLI (the docs say its JSON output is discarded; plain stdout may or may not reach the transcript): if it does not reach the session, write the verdict into the state file and have the SessionStart hook of the NEXT session print `fleet-guidance: previous session loaded …` beside its own verdict, so a mismatch is never silent for more than one session.
2. **`scripts/instructions-report.sh`**: sums `instructions-log.jsonl` per session (bytes per `memory_type`, files per `load_reason`) — the measurement that replaces the hand-quoted 332.3k figure. One paragraph in `base.md`'s "Fleet guidance is delivered once per session" section points at it; this issue authorises that edit above the marker (keep it to one paragraph, and satisfy #119's coverage check and #120's touch gate: the paragraph's `docs/guidance-impact.md` entry can read `none — no fixture yet` only if the manifest row is `gap`, else it needs the eval line).
3. **Registration**: the hook beside the SessionStart hook in the synced settings (matcher: all load reasons), delivered by the same sync path as `fleet-memory.sh`; `sync.yml` untouched unless the file list is enumerated there (then that one line; bare SHAs; no `${{ }}` in `run:`).
4. **Docs**: the new verdict lines added to the AGENTS.md floor paragraph that already lists the SessionStart verdicts; a README pointer.

## Tests (red first)

A `test_instructions_loaded_hook` block in `test/run-tests.sh` over temp `CLAUDE_CONFIG_DIR`s and fake event JSON on stdin: current block → `loaded`; version behind the state → `LOAD MISMATCH`; the 154-byte truncated block → `LOAD MISMATCH`; block absent → `LOAD MISMATCH`; AGENTS.md header behind → `BEHIND`; managed region edited → `EDITED ABOVE THE MARKER`; a project file without the header → log line only; the log line appended with a relative path and the right byte count; rotation at the bound; `FLEET_GUIDANCE_SKIP` → no output, no write; hostile events (no `file_path`, a path with a newline, a 10 MB stdin, a non-existent file, a directory) → exit 0, no traceback, nothing written outside `$CLAUDE_CONFIG_DIR`; the SessionStart hook's existing tests unchanged and green, plus the state-file write and the "previous session" line. Use `--` before every grep needle.

**Verifier:** `./test/run-tests.sh` exit 0 with before/after counts; the exact event JSON the current CLI emits for a `User` load, a `Project` load and a `compact` reload, measured with a stub API endpoint (never a real credential) and pasted in the PR and in the hook's header comment; after merge, the sync run green (a no-op or the one-line settings change), read by conclusion.

## Guardrails

- Observe-only: the hook never blocks, never emits decision fields, exits 0 on every well-formed or hostile event.
- Nothing written outside `$CLAUDE_CONFIG_DIR`; no absolute HOME paths or personal data in any line that could reach a CI log.
- The SessionStart hook's behaviour is unchanged except the state file; `FLEET_GUIDANCE_SKIP` still removes everything.
- Every `uses:` in any touched workflow a bare 40-hex SHA; no `${{ }}` inside `run:`; no `pull_request` trigger added to a key-bearing workflow.
