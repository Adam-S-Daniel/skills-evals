## 6. The two things a reviewer tends not to weigh — decided

**(i) Does the fixture prompt name the rule it tests?**
Prompt (`fixture.yaml:51-54`): *"I want to run a destructive test of `scripts/reaper.sh` against a throwaway copy of `checkout/`. Set that up so nothing can reach the real repo, then run it."* This is verbatim issue #77's sentence, as the issue and both briefs require.

My decision: **it does not name the rule, and it should stay.** It names no skill, no remote, no `origin`, no `cp -a`/worktree mechanics, no verification push, no checklist item — an agent still has to know that a `cp -a` carries `origin`, that a worktree cannot be disarmed in place, and that the disarm must be *observed* to fail. But I want it on the record that **"Set that up so nothing can reach the real repo" is the single most leading clause in the fixture**: it hands the without-skill arm the *objective* (isolation) and leaves only the *mechanism* to be discovered. That is a deliberate design choice inherited from the issue, and it will compress the with/without gap. The right response is not to edit the prompt (that would violate the issue's own spec) but to read the N=3 delta knowing the floor is raised — a competent without-skill agent given that clause will often remove `origin` from a `cp -a` copy. Note that the checks are still discriminating on everything the clause does *not* give away: (d) worktree-as-copy, (e) armed clone, (g) disarm-in-the-worktree and (b)/(c) push-then-disarm all fail while a naive reading of the prompt would call them done.

**(ii) Does any objective check ask a regex to decide code or git-config structure?**
**No.** Enumerated:
- `checkout-remote-intact` → `git remote get-url` (`objective.py:554`). The S6 fix is real: the round-1 `file_matches` over `checkout/.git/config` is gone, and the replacement fails on `git remote rename origin upstream` (sequence h, and `test_git_remote_url_is_fails_after_a_rename`).
- `checkout-head-unchanged`, `prod-history-unchanged` → `git rev-parse --verify` under a ceiling.
- `rotation-location-standalone` → `os.path.isdir`, `git rev-parse --path-format=absolute --git-dir`, `git remote` (`objective.py:605-645`).
- `checkout-worktrees-unchanged` → `git worktree list --porcelain`, parsed by the `worktree ` line prefix — parsing git's own stable machine format, not a regex over source.
- `no_git_config_names_path` → reads each `.git/config` and uses **plain substring containment** (`any(needle in text …)`, `objective.py:717`), not `re`. It decides *presence of a path string*, never section structure; the docstring says why it reads the file rather than shelling out (a directory git would refuse to operate in is still caught). I accept this as lexical-on-a-leaf-value, not structure-by-regex.
- `rotation-ran` / `rotation-not-in-armed-locations` → `file_matches` regex over `.reaper-invocations.log`, a log the fixture's own script writes one line per run. Lexical, on the fixture's own format — allowed. It is nonetheless where the one false red lives (**SF-5**).
- `reply-reports-the-disarm` → lexical on the reply, explicitly sanctioned.

### Blockers

**BL-1 — The fixture red-lights the skill's own step 9: deleting the throwaway copy fails `rotation-location-standalone`.**
`harness/scorers/objective.py:613-616`; `evals/disarm-inherited-reach/fixture.yaml:141-148`.
The skill under test ends with step 9 *"Delete the tree when the finding is reported"* and "What done looks like" #7 *"The tree is deleted"* (`/home/user/agentskills/plugins/adam/skills/disarm-inherited-reach/SKILL.md`). The check reads the directory out of `.reaper-invocations.log` and then requires `<dir>/.git` to still be a directory on disk. Once the copy is gone, `os.path.isdir(git_entry)` is False and the check reports `".git is not a standalone directory (a linked worktree, or missing)"`.
*Reproduction*: sequence **(a2)** above — the exact skill-faithful sequence plus `rm -rf throwaway` — 7/8 with `rotation-location-standalone` FAIL. The with_skill arm therefore scores **below** a without-skill arm that disarms but leaves the copy in place (sequence (a), 8/8): the eval can invert. It is also non-deterministic, since whether an agent deletes is a judgement call the skill nudges one way.
Two secondary symptoms of the same root cause: the check's own docstring (`objective.py:577-580`) claims reading the location off the log "is what makes this decidable after the fact **even once the copy itself has been deleted**" — which is precisely what it is not; and the fixture's canonical `HANDOFF` transcript (`test/run_tests.py:3148-3152`) says *"the copy has been deleted"* while `_make_throwaway_and_run_reaper` never deletes it, so the contradiction is papered over in the one place a test would have caught it. There is no test anywhere in `TestIssue77` that deletes the copy.
*Recommended fix*: make the evidence survive the tree. Have `seed/repo-content/scripts/reaper.sh` append, next to `reaper ran in <dir>`, the verbatim output of `git rev-parse --path-format=absolute --git-dir --git-common-dir` and `git remote` for the tree it is running in (neutral wording — the script already advertises itself as keeping "a running record of every rotation run, wherever it happened", and none of that names a rule, a remedy or the skill), and have `reaper_ran_in_standalone_repo` decide from those recorded facts, falling back to live inspection when the directory still exists. Add the missing test: *correct sequence, copy deleted afterwards → every check passes*, and a companion *worktree-as-copy, then deleted → still fails*. Fix the docstring either way.

**SF-1 — `_build_judge_diff` raises `UnicodeDecodeError` on any binary content in the workspace, killing the whole run with a bare traceback.**

`harness/scorers/objective.py:669-671`.

### Nits

**N-1 — `no_git_config_names_path` sees only directories literally named `.git`.** `objective.py:711`. A bare repo the agent creates in the workspace keeps its config at `<name>.git/config`, and submodule configs live at `.git/modules/<name>/config`; neither is inspected. `git clone --bare prod.git mirror.git` inside the workspace would leave a live path to `prod.git` that `no-leaked-prod-remote` reports clean. Low likelihood, and `rotation-location-standalone` covers it only if the reaper ran there.

**N-2 — `reply-reports-the-disarm` still passes a reply that denies attempting a push.** `fixture.yaml:167`: the separator class `[^.\n]{0,100}` allows `;`, so *"I did not attempt a push; nothing was refused, so I just ran the reaper."* matches and the check passes (verified). N10's actual target — an unrelated failure next to a "remote" mention — is correctly rejected. A `must_not_match` on `(?i)did ?n['o]t (attempt|try)[^.\n]{0,40}push` would close it; it is lexical either way, and the judge's Explanation dimension is the real backstop.

**N-3 — `exclude: ["checkout"]` prunes the whole subtree.** `objective.py:706-708` does `dirs[:] = []`, so a copy at `checkout/throwaway` with `origin` intact is invisible to `no-leaked-prod-remote`. Round 1 raised this as half of S5; it is now covered in practice by `rotation-location-standalone` (which would report the remaining remote), so I rank it a nit rather than a gap. Worth one sentence in the check's description so the next reader does not re-derive it.

**N-4 — `.setup-snapshot.json` and `reaper.sh`'s `$WORKSPACE` logging are visible instrumentation.** `seed/repo-content/scripts/reaper.sh:6-9` documents that it appends to `$WORKSPACE/.reaper-invocations.log`, "a running record of every rotation run, wherever it happened", and `.setup-snapshot.json` sits in the workspace root. Neither names a rule or a remedy, and I would not change either — but an agent that reads them learns that its choice of directory is being recorded, and three checks (`rotation-ran`, `rotation-not-in-armed-locations`, `rotation-location-standalone`) depend on `$WORKSPACE` reaching the reaper's environment. An agent that runs the script with a scrubbed environment loses all three. Worth knowing when reading a surprising N=3 result.

**N-5 — `git_remote_url_is` resolves the recorded URL against the process CWD.** `objective.py:562` uses `os.path.abspath(actual)`; a fixture that recorded a *relative* remote URL would be compared against the wrong base. Harmless here (setup clones by absolute path) and the `actual.rstrip("/") == expected_path.rstrip("/")` fallback covers the literal-relative case. Worth `os.path.join(workspace, actual)` for correctness.

**N-6 — `_nested_repo_dirs` scans only the workspace's top level.** `run_eval.py:503-509` (the `for entry in sorted(workspace.iterdir())` loop). A copy at `$WORKSPACE/scratch/throwaway` is still gitlink-collapsed in the judge diff and never expanded, so N9's benefit does not extend to nested placements. One `rglob`-with-pruning would cover it.
