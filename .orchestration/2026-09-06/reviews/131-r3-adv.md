## NITS

### N-1. Hard wrapping splits a fact and the check misses it
`\b(?i)March 2027\b` (`recruiter-reply/fixture.yaml:146`) and
`\bSections?\b[^.\n]*\b508\b` (`proposal-bio/fixture.yaml:122`) both die on a
line break. Measured: `…contracted through March\n2027, so…` FAILS
cites-both-facts; `…a clean Section\n508 audit.` FAILS. Note the asymmetry —
`judge._normalize_draft_text` unwraps a draft for the judge while
`objective.py` scores it wrapped. Low likelihood (judge.py's own docstring
says a model's reply is one long line per paragraph), but the fix is free:
`\bMarch\s+2027\b`, and `[^.]{0,80}` instead of `[^.\n]*`.

### N-2. `_normalize_draft_text` is O(n²) on a hard-wrapped draft
`judge.py:452` (`out[-1] += " " + line`). Measured: 0.30 MB → 0.06 s,
1.22 MB → 0.69 s, 4.88 MB → 15.1 s, 12.2 MB → **94 s**. Nothing bounds a
transcript. Build the paragraph in a list and `" ".join` it once.

### N-3. A hard-wrapped **bulleted** draft does not normalise like its unwrapped twin
`_LIST_ITEM_RE` blocks joining in both directions, so a wrapped bullet's
continuation line stays broken while a model's bullet is one line. Measured:
`_normalize_draft_text(wrapped) != _normalize_draft_text(unwrapped)` for a
bulleted pair, where the prose pair is equal. Harmless today (no committed
reference has bullets) but it is the line-shape tell the function exists to
remove, and `test_a_hard_wrapped_draft_normalises_like_its_unwrapped_twin`
uses prose only.
