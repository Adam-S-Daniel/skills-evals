## 7. New findings

No blockers and no should-fixes. Four notes, each with its measurement.

**Note 1 — the decision's cost, measured: a zero-touch PR on a pre-manifest fork now fails CI at exit 2 as soon as the base branch has grown a section since the fork.** `scripts/check-guidance-touch.js:481-492`. `$SP/r5hist/w_newsection`, `ev-w1.json`: fork predates the manifest, main later adds the manifest **and** `## Heading Three`, the PR changes only `README.md` → head `2`, `agents-md/eval-coverage.yml is absent at b3faa71… and section "heading-three" could not be matched by heading there — merge or rebase…`; `6be2059` gave `0`. The same fires on the merge-base side, where `required: false` no longer suppresses it (`$SP/r5hist/d_mbside`, `ev-d1.json` → exit 2 naming the **merge-base** sha, a commit the PR author never sees in the UI). This is the design decision as written, not a defect, and I verified the remedy it names actually clears both (`ev-w1b.json`, `ev-d1c.json` → exit 0), so it self-heals rather than trapping anyone. Worth a sentence to Adam only because the window "branches forked before 2026-09-04" is exactly the population that now sees a red X on a PR that changed nothing in `agents-md/`.

**Note 2 (nit, NOT a repeat) — a body-boundary escape S1 does not cover: an entry whose body ends in `prose` + `---` is truncated at that line, because markdown-it reads it as a setext `h2`.** `scripts/check-guidance-touch.js:573-576` inherits `extractHeadings`' boundaries. `$SP/r5hist/b_setext`, `ev-b_setext.json`: base entry `## 2026-09-04 — heading-two — edit` / `- Motivation: m` / `- Change: c` / blank / `ORIGINAL trailing prose` / `---`. `ORIGINAL trailing prose\n---` is a setext heading, so the dated entry's body stops above it; rewriting that line to `REWRITTEN trailing prose`, with a real touch elsewhere, is **exit 0** on head **and** on `6be2059`. Same family as the hole S1 just closed, different mechanism, **pre-existing** (not introduced this round) and never previously reported.
