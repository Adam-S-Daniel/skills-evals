## should-fix 1 — `min_ranked_share` is applied over the 8-week union only, so S2's failure reproduces verbatim inside the enter window

`harness/roster.py:725-732` (the relative floor, inside `_census_verdict`, which is
handed the UNION totals from `:784-787`) vs `harness/roster.py:810-811`:

```python

exit_usable  = usable and exit_ranked_total  >= policy["min_ranked_turns"]
```

left at the union. So take S2's own census — `other` dominating, ~20 genuinely ranked
turns — put the 20 turns *inside the enter window*, and park enough real ranked volume
in weeks 5-8 to carry the union ratio over 1%. The union guard passes; the enter window
is 20 ranked turns against 400,020 raw; and a **non-newest** model is seated on it at a
published "100.0%".

**Exact input** (`_atk/a1_enter_share.py`, runnable standalone):

```python

              created={"claude-sonnet-5-0": "2026-01-01T00:00:00Z",       # newest sonnet
                       "claude-sonnet-4-5": "2025-09-29T00:00:00Z"})
enter, exit_only = W4, [w for w in W8 if w not in W4]
counts = {"other":             {w: 100000 for w in enter},      # 400,000 raw, enter window
          "claude-sonnet-4-5": {enter[0]: 20},                  # exactly min_ranked_turns
          "claude-opus-4-1":   {w: 1000000 for w in exit_only}} # union ratio -> 0.909

```

**Measured:**

```

ENTER raw=400020  ranked=20      ratio=0.000050

arm claude-haiku-4-5  | newest model in the haiku tier, 611 days old (past the 7-day cooling-off)
arm claude-sonnet-4-5 | carries 100.0% of rankable census usage over the last 4 weeks (at or above the 10% entry bar)
```

`claude-sonnet-4-5` is not the newest in its tier; its only route to a seat is that share,

**Fix:** compute `raw` alongside `ranked` for each window (`_in_window_totals` already
returns both — the calls at `:802-809` discard the raw half with `_`), and gate
`enter_usable`/`exit_usable` on `ranked >= min_ranked_turns and ranked >= min_ranked_share * raw`
for that window. Test with the census above: `claude-sonnet-4-5` must not be seated.

### Trust boundary, weighed honestly

Writing `previous.json` needs push to `eval-results`. Whoever has that already has a
**census-only** dilution primitive that needs no plant at all: an *invented dated snapshot
of a real catalogue id* folds onto that id and is attributed with no history required
(`_atk/a7b_snapshot.py`, census key `claude-sonnet-4-5-20991231` at 1,000,000/wk):

```

```

**Measured identical at `b743d50`**, so that one predates round 5 and is not a regression.

and no warning, so a bad entry from *any* source (a plant, a one-off API oddity, a future
`refresh_models.py` bug) is permanent evidence that nothing will ever surface.

**Fix:** store history with an age, not as a bare set — e.g.
`catalogue_seen: [{id, last_seen}]` (or a parallel `catalogue_seen_at` map), drop entries
not observed in the last N runs, and cap the list length with a count-only warning past it.
That keeps the property DESIGN.md property 5 promises (a since-retired real model stays
attributable for a bounded window after it leaves) while making a plant age out on its own.
Whatever is chosen, DESIGN.md `:343-356` and `roster-policy.yml:50-60` should say out loud
that this list is read back from an untrusted branch and how an entry leaves it — neither
currently mentions either.
