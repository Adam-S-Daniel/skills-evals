### 1. `_is_attributable` discards census usage recorded under an id that IS in the Models API catalogue — regression introduced by round 3's own fix
**Severity: should-fix** · `harness/roster.py:193` (and the `_in_window_totals` caller at `:422`, `usage_share` caller at `:230`)

```python
return folded in api_ids or candidate in previous_arms or folded in previous_arms
```

The check is on `folded`, never on `candidate`. When the catalogue publishes only dated ids — the case `alias_map`'s docstring (`:154-156`) and `evals/roster-policy.yml:47-49` both name as legitimate, and the shape the real `/v1/models` returns — `aliases` folds the dated id onto its undated alias, which is *not* an api id. A single turn recorded under the undated spelling anywhere in the census is enough to poison the dated one.

**Exact input** (`_atk/t9.py`, runnable standalone):
```python
models_doc = {"fetched_at": "2026-09-04T11:00:00Z", "models": [
    {"id": "claude-haiku-4-5-20251001",  "created_at": "2025-10-01T00:00:00Z"},
    {"id": "claude-sonnet-4-5-20250929", "created_at": "2025-09-29T00:00:00Z"}]}
census_doc = {"generated_at": "2026-09-03T00:00:00Z", "weeks": W, "counts": {
    "claude-sonnet-4-5-20250929": {w: 500 for w in W[:4]},   # 2000 turns, id IS in api_ids
    "claude-sonnet-4-5":          {w: 1   for w in W[:4]}}}  # 4 turns
roster.compute_roster(models_doc, census_doc, POLICY, None, NOW)
```

**Observed** (2004 turns in the census, 2000 of them under a verbatim catalogue id):
```
arm claude-sonnet-4-5-20250929
    census published but holds no usage this policy can rank over the window
    (every count in these weeks is `other` or an id the tier ladder cannot place);
    fell back to newest per tier — newest model in the sonnet tier, 340 days old
```
`_in_window_totals(...) == (2004, 0)`. The published sentence is flatly false, and it is published to the public branch in *every* arm's reason (DESIGN.md property 2 is precisely that these reasons are the artifact).

**It is a regression, measured.** Same input against `fc5de5c` (the previously reviewed head, before `c0e8838`): `carries 100.0% of census usage over the last 4 weeks`. So round 3's fix traded one wrong answer for another.

**It also publishes a materially false percentage in the mixed shape** (`_atk/t2.py` case 9): api dated-only, census `{claude-sonnet-4-5: 100000, claude-haiku-4-5-20251001: 5}` →
`claude-haiku-4-5-20251001: carries 100.0% of census usage over the last 4 weeks` — for a model that carried 5 of 100,005 turns — and `retired claude-opus-4-1-20250805 — below the 2% exit bar (0.0%)`.

It also breaks the invariant stated four lines above the two alias maps (`:512-514`): *"USAGE folds over both, so a seat keeps the usage recorded under either spelling of itself."*

**Fix (both halves verified in an isolated copy):**
- `candidate in api_ids` added to the disjunction closes the exact-catalogue-id half (case 8/10).
- Additionally attributing against the *alias-folded* api id set — `{aliases.get(i, i) for i in api_ids}` — closes the "usage only under the undated alias" half (case 7).
- Neither reopens round 3's proxy hole: `proxy-router-claude-sonnet-4-5` still lands unattributable, `ranked_total == 0`, nothing retired.

**Coverage gap:** the full suite is 282/282 green *with the patch applied*, i.e. no existing test exercises either direction. A regression test on a dated-only catalogue whose census also carries the undated alias is what would have caught this.

**Property 3 is intact** — the failure direction is conservative (a false fallback, never a false retirement), which is why this is should-fix and not blocker.
