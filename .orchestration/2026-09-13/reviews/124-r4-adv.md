**S1-new — a FIFO at `instructions-receipt.state` hangs `fleet-memory.sh` unboundedly and leaks a blocked `grep`. Introduced by this PR (`main` does not hang), at the one site R2-S2's hardening did not reach.**

Reproduction:

```bash
C=$(mktemp -d); mkdir -p "$C/.home"; mkfifo "$C/instructions-receipt.state"
HOME=$C/.home CLAUDE_CONFIG_DIR=$C timeout --foreground 60 bash .claude/hooks/fleet-memory.sh </dev/null
```

| tree | rc | wall | orphan left |
|---|---|---|---|
| head `8ec4cb3` | **124** | 60 008 ms | `grep -m1 -- ^unread= …/instructions-receipt.state.claim.<pid>` blocked for ever |
| `0d73ac4` | **124** | 25 009 ms (my bound) | `grep -m1 -- ^unread= …/instructions-receipt.state` |
| `main` `5f13def` | 0 | 39 ms | none |

`report_previous_session` gates on `[ -r "$RECEIPT_FILE" ]`, which is true for a FIFO; the claim `mv` renames the FIFO happily; `grep -m1 -- '^unread=' "$claim"` then blocks opening it with no writer. Every sibling read in this programme already uses the right pair — the hook's `read_bytes`/`open_owned` use `os.path.isfile` + `O_NONBLOCK`, `instructions-report.sh` was given the same pair this round (`f1c8171`), and the registrar was given `-e && ! -f` (`83b30cd`). The receipt read is the one that was left on `-r`.

Mitigations, stated so the grade is not oversold: fleet-memory is registered with `timeout: 30`, so a session start stalls 30 s rather than for ever; and because the claim renamed the FIFO aside, only the *first* session start after the plant stalls. What does not expire is the orphaned `grep`, which is precisely the R2-S2 property the round-2 remedy was written to obtain.

**Fix (one word):** `[ -f "$RECEIPT_FILE" ] || return 0` in place of `[ -r … ]`, and, belt-and-braces, read the claimed copy with `head -c` on a non-blocking open rather than a bare `grep`. REPEAT: same defect class as R2-S2 (FIFO hang + leaked child), at a new site; not a return through a remedy, but the site the remedy's own invariant should have enumerated.

**S2-new — `restore_receipt` cannot tell "a newer receipt won the name" from "this filesystem has no hard links", and in the second case destroys the receipt silently and leaks an orphan claim file. Arrives through this brief's S1 remedy.**

`ln` is shadowed on PATH with `#!/bin/sh\nexit 1` — the same technique the brief prescribes for S2 — which is exactly what a filesystem without `link(2)` (exFAT/FAT, some network and fuse mounts) presents:

```
unread=1 : announced, then     RECEIPT GONE,  no "could not clear" line, rc 0
unread=0 : (nothing announced) RECEIPT GONE,  orphan `instructions-receipt.state.claim.<pid>` left behind
```

`mark_receipt_read` sets `cleared=true` as soon as the `sed` into the tmp succeeds, so the loud line never fires; `restore_receipt` then fails the `ln`, does **not** `rm "$1"`, and the caller's `rm -f "$claim"` / `rm -f "$tmp"` finish the job. The `unread!=1` path has no such `rm`, so the claim file simply stays — one per lost receipt, never cleaned, in the user's config dir.

This falsifies the invariant written two lines above it in the same function: *"the CLAIMED ORIGINAL when it did not, so a failure costs a repeated line and never the verdict itself."* On this filesystem a failure costs the verdict and produces no line at all.

**Fix:** distinguish EEXIST from everything else, which the shell can do without `errno`:

```bash
restore_receipt() {
    if ln "$1" "$RECEIPT_FILE" 2>/dev/null; then rm -f "$1" 2>/dev/null
    elif [ -e "$RECEIPT_FILE" ]; then rm -f "$1" 2>/dev/null   # a newer receipt won the name
    elif mv "$1" "$RECEIPT_FILE" 2>/dev/null; then :           # no hard links here
    else echo "fleet-guidance: could not put the previous session's receipt back — its verdict is lost."
    fi
}
```

REPEAT: this is R2-N4/S2's class — a write that fails and says nothing — returning through the remedy prescribed for S1, which is the shape this round was convened to catch.

### Nit

**N2 — `state_unusable()` is still silent for the simplest corruption there is.** `5460b98`'s headline is "an unusable state file of ANY shape leaves a mark". Measured: directory, FIFO, socket, dangling symlink → `LOAD MISMATCH — fleet-guidance.state is not a regular file …`; over-cap → the size sentence. But a **0-byte** state file, a `version=` with an empty value, and a symlink to an unrelated regular file (`/etc/hostname`) all produce **no verdict, no receipt, no report line** — `lexists`/`isfile`/`getsize`/`access` all pass, `read_kv` returns a dict with no usable `version`, `fleet_verdict` returns None. A zero-byte state file is what an interrupted or ENOSPC write leaves behind. Fix: treat "read, but carries no `version`" as a named reason, distinct from the deliberately-silent absent case.

**N3 — the same gap on the payload.** `c3ee0c7` gives `cannot compare — … is empty` and `… is N bytes, past the 4194304-byte cap`, both measured and correct. **N4 — the registrar's opened-fd guard checks `S_ISREG` but not `st_nlink == 1`.** Measured: a settings.json hard-linked to a sibling is written through, and the sibling changes with it (`changed=YES`). The hook's own `open_owned` refuses `nlink > 1` for exactly this reason; the registrar was hardened this round for type and not for links.
