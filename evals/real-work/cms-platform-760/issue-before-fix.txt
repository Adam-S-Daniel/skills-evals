Tags that differ only by case (quotes / Quotes) show as two identical cards and one tag page drops the other's posts

Found in the 2026-10-06 exploratory round 2 (adamdaniel.ai visitor pass, local build at platform v0.1.148).

**Severity:** minor (no live post has a case-variant tag today, but when one appears, a post silently drops off its own tag page).

## Steps

1. Have one post tagged `quotes` and another tagged `Quotes`.
2. Open `/tags/`, the home Tags row, and `/tags/quotes/`.

Viewport: 1440×900 Chromium (also seen in Firefox home).

## Seen

- Two identical cards, both "QUOTES 1", both linking to `/tags/quotes/`.
- `/tags/quotes/` lists only the `Quotes` post; the `quotes` post is gone from its own tag page.

## Expected

Tags that slugify the same are one tag: one card with the combined count, and one archive (and tag feed) listing every post.

## Cause (verified at origin/main 0c0bf38)

- `theme/lib/cms-platform-theme/auto_tag_pages.rb` `summarise`: `post_tag_lists.flatten.compact.uniq` is case-sensitive, so `quotes` and `Quotes` are two names with the same slug; `count` matches by exact name, giving "1" each.
- The generator mints one `TagPage` per missing name, both with permalink `/tags/quotes/`; the later one wins.
- `theme/_layouts/tag.html` l.42 filters `post.tags contains tag_label`, an exact string match, so the winning page shows only its own spelling.
- `theme/lib/cms-platform-theme/tag_feeds.rb` builds its list from post tags the same way; worth checking in the same fix.

Grouping by slug (keeping one display name, e.g. the `_tags/` entry's or the most used) in `summarise`, and matching posts by slug in the layout, would fix all three. https://github.com/Adam-S-Daniel/cms-platform/issues/735 (via #746) now warns editors about near-duplicates, which makes this rarer but does not stop it.
