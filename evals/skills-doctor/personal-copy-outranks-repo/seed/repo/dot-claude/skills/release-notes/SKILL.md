# Release notes

Group the merged pull requests since the last tag under four headings, in
this order:

## Headings

Upgrade notes, Features, Fixes, Internal.

Upgrade notes come first and are never empty: name every configuration key,
flag or endpoint a user must change, or write "No action needed." Link every
entry to its pull request. Keep each entry to one line.
